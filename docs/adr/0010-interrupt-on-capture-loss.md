# Interrupt active capture on confirmed sample loss

Status: accepted, 2026-10-24.

Before a capture block reaches `LoopEngine`, the Windows audio host must determine whether its input samples are valid and continuous. If samples were confirmed lost, dropped, or replaced by synthetic silence while REC or overdub is active, interrupt at the earliest safe processing boundary. Do not silently insert silence, skip samples, or conceal the gap while capture continues. A low buffer occupancy warning, delayed callback, or normal adaptive resampling is not confirmed loss and must not interrupt by itself. Warning thresholds, buffer sizing, and drift-controller tuning remain experimental, but confirmed loss is never tolerated during active capture based on a fault-count threshold.

Use existing `LoopEngine::interrupt()` semantics: stop and reset transport, disable monitoring, discard unfinished initial recording, and retain completed recordings and overdub additions already written. Report that an interrupted overdub may be partial. Do not resume capture automatically. The interruption reason and relevant diagnostics are recorded outside the real-time callback. When no REC or overdub is active, keep playback running; zero-fill missing monitoring input or discard stale capture data as needed to restore bounded latency and report the discontinuity without blocking the audio thread. Host-detected loss/device failure takes priority over queued ordinary UI commands; interruption advances the session generation so pending old-generation commands are rejected and cannot restart capture automatically.

The user-facing state explains the session-wide result: transport stopped and reset, monitoring off, unfinished initial recording discarded, completed recordings retained, and any in-progress overdub retained only through the samples already written. Focused engine/host tests must cover initial REC, overdub, and playback-only interruption with exact retained/discarded sample outcomes. This is a correctness response to known input loss, not a latency threshold or a generic response to transient buffer occupancy.
