# Prefer low-period shared WASAPI for the initial Windows prototype

Status: accepted, 2026-10-24.

For each selected capture and render endpoint, the initial Windows audio host should request the lowest shared-mode period supported by that endpoint and driver, using the Windows low-latency shared-stream capability where available. If that initialization is unsupported, it may explicitly restart that stream in regular shared mode and must report the negotiated rate, period, buffer configuration, and fallback status. Shared mode is the ordinary-user default because other applications can continue using the endpoint; regular shared fallback preserves availability but does not satisfy or prove the low-latency goal. Treat the minimum period as a starting point: capture and render must be validated together, and any larger-period retry requires a controlled restart outside active recording or playback. Initialization failures must distinguish unsupported settings from busy, disconnected, and other failures. Exclusive mode and ASIO are outside the initial prototype. The prototype uses explicit WASAPI control through Windows bindings or `wasapi-rs` plus underlying Windows APIs as needed, rather than forking or extending CPAL to preserve a generic stream API; see [ADR-0006](0006-explicit-wasapi-prototype.md). Accept the strategy only after measuring complete microphone-to-output latency and dropouts under representative load; buffer duration and API estimates are diagnostics, not round-trip measurements. This strategy belongs to the Windows host and can change without changing the platform-neutral host boundary or portable LoopEngine.

Microsoft documents `IAudioClient3` shared periods as endpoint-supported values and notes that the low-period shared path preserves system audio sharing. Those API properties do not establish a latency or stability guarantee for LoopBeats on any device. See [InitializeSharedAudioStream](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient3-initializesharedaudiostream) and [Exclusive-Mode Streams](https://learn.microsoft.com/en-us/windows/win32/coreaudio/exclusive-mode-streams).
